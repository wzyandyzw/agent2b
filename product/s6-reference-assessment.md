# S6 参考实现拆解与适配判断

> 调研日期：2026-10-29  
> 结论：与汇甬第一阶段“全公司通用数字员工 CLI Demo”高度匹配，可以作为技术骨架；不能直接作为完整企业平台上线。

## 两个压缩包

| 包 | 内容 | 用途 |
|---|---|---|
| `s6-env-w1.zip` | W1 模拟 ERP、接口规范、OpenAPI、故障注入和测试 | 做离线联调与异常测试 |
| `shenwei-agent-product-W1-all-tags.zip` | 10 个完整版本快照，从需求文档到 w1 发布 | 查看 Agent 实现过程和复用代码 |

建议以 `shenwei-agent-product-w1-fix1` 作为参考基线。`w1.9`、`w1` 和 `fix1` 主体相同，`fix1` 修复了测试中的假密钥扫描问题。

## 已实现能力

- CLI 对话、模型调用、多轮工具调用和会话续跑。
- 三个 ERP 只读工具：查产品规格、库存交期、物流。
- 工具参数校验，未知工具和非法调用不会进入业务系统。
- 模型、ERP 超时和错误分类，只读超时有界重试。
- 步数、单次超时、总时长预算。
- JSONL 执行事件与只读回放，关键请求可追溯。
- 可替换的模型和 ERP 接口，不把业务逻辑写死在 Loop 中。
- 40 条单元测试通过；离线 CLI 已实际跑通。
- 模拟 ERP 的 16 条测试通过，覆盖幂等、分页、错误体、事件和账本。

说明：ERP 测试在本机首轮出现过一次 Webhook 投递失败，清理代理相关环境后全量重跑通过。后续接入 SCRM 事件时仍需做投递稳定性复验。

## 尚未实现

- 只有三个只读工具，没有报价、工单或 SCRM 写入。
- 没有 SCRM 和知识库模拟环境；需要等课程后续材料或自行建设。
- 没有审批流、主管授权、多岗位 Agent 或多租户产品。
- 没有自动知识检索，只有对话历史和工具结果上下文。
- 没有 Web 前端和 Java 平台实现；目前只是占位。
- 没有自动评测体系和正式业务案例集。
- 会话持久化和事件记录面向本地运行，不适合直接作为生产平台。

## 与全公司数字员工 Demo 的适配

### 可直接复用

- AgentLoop、上下文构建、工具注册与执行。
- 参数校验、错误分类、预算和事件回放。
- 模型客户端抽象、测试替身和故障注入方法。
- “价格只能由业务系统计算，模型不能自由填金额”的原则。
- CLI 交互、会话续跑和“一次任务多次调用工具”的通用执行方式。

### 需要改造

- 从单一 ERP 只读工具扩展为面向全公司的工具目录。
- 接入客户、订单、物流、应收、工单、CRM 和企业知识。
- 增加文档、表格、搜索及模拟写操作工具。
- 将当前单体工具注册扩展为可安装、可停用的插件/技能体系。
- 把汇甬产品和历史案例加入知识库，作为重点演示数据。
- 将本地会话扩展为可表示跨部门任务的通用 Case。

### 必须自建

- 汇甬产品、案例、方案、报价和测试数据的知识库。
- 工程师审批、主管授权和不可逆动作控制。
- 客户、项目、设备、合同和订单的统一业务模型。
- 售前方案的业务评测集和 Badcase 回流。
- 多角色、多租户、权限、部署和运营能力。

## 推荐落地方式

1. 保留两个压缩包作为参考资料，不把 10 个版本全部展开进正式代码库。
2. 以 `fix1` 为基线搭建单 Agent CLI。
3. 接入模拟 ERP、CRM、知识库和文件工具。
4. 用 5 个跨部门任务跑通通用能力，而不是围绕单一岗位做特化。
5. Demo 验证通过后，再实现 Web、正式权限、审批和生产系统连接。

首个可交付目标是“全公司通用数字员工 CLI Demo”，企业知识检索和跨系统任务是演示重点。
