# 汇甬新材全公司数字员工 Agent

> 第一阶段：CLI Demo  
> 目标：用同一个 Agent 连接 ERP、CRM、知识库和企业通信工具，完成跨部门任务。

## 产品定位

不是只服务销售或售前岗位，而是为汇甬提供一个通用企业 Agent。员工用自然语言提出任务，Agent 自主理解需求、查询系统和知识、调用工具、生成结果，并在需要时请求确认。

第一阶段用 CLI 验证核心能力，不开发 Web 前端和完整企业管理平台。

## 第一阶段范围

### 可以做

- 一次对话内完成多步骤任务，必要时连续调用多个工具。
- 查询 ERP：产品、库存、交期、客户、订单、物流、应收和工单。
- 查询客户、联系人和应收：首版通过模拟 ERP 客户对象演示，CRM/SCRM 接口预留。
- 查询企业知识：产品资料、项目案例、制度、方案和模板。
- 预留公开搜索扩展；首版不依赖外部搜索完成业务事实。
- 生成 Markdown 报告、技术方案摘要、邮件和跟进内容；Word、Excel 在后续阶段接入。
- 按 ERP 规则计算报价，但只返回未落账草稿。
- 保存会话、恢复任务、记录每次工具调用，并支持只读回放。

### 暂不包含

- Web 前端、移动端和成品工作台。
- 多 Agent 自主协作和复杂组织架构。
- 真实企业系统的生产写入。
- 真实 CRM/SCRM、OA、飞书与付费搜索接入。
- 完整审批流、计费、租户隔离和正式运营后台。
- 系统落账、合同发送和对外消息发送。

## 通用能力架构

```text
CLI
  ↓
Agent Loop
  ├─ 企业知识检索
  ├─ ERP / CRM / OA 工具
  ├─ 文档、表格和搜索工具
  ├─ 权限、参数校验和预算
  └─ 事件日志、回放和会话历史
```

模型负责理解与规划；ERP、CRM 和知识库是事实来源；业务规则负责计算；工具负责执行；用户负责确认关键动作。

## Demo 场景

用少量跨部门任务证明“通用 Agent”而不是“单一功能机器人”：

| 场景 | 用户一句话 | Agent 要完成 |
|---|---|---|
| 客户全景 | 汇总某客户今年订单、物流、回款和最近沟通 | 跨 ERP、CRM 和知识库汇总并提示风险 |
| 订单异常 | 找出承诺期内未签收的订单并处理 | 查订单和物流，定位原因，拟工单和客户回复 |
| 技术售前 | 根据客户溶剂和处理量给出方案 | 查参数、案例和选型规则，生成方案初稿 |
| 报价准备 | 为某客户生成报价和内部说明 | 按报价规则计算，生成文档，等待确认 |
| 经营复盘 | 汇总本周订单、回款和售后异常 | 跨系统查询，生成周报和行动清单 |
| 行政办公 | 把会议记录整理成任务和跟进邮件 | 读取文件，结构化任务，生成结果 |

## 首个 CLI Demo 交付

1. 通过命令输入一个自然语言任务。
2. Agent 判断需要哪些工具，并展示执行过程。
3. Agent 给出有事实来源的答复或文件。
4. 缺参数时主动追问，系统失败时不编造结果。
5. 报价只计算、不落账；系统写入在后续阶段接入。
6. 保存会话，可继续聊天、查看事件和回放。

## 技术基线

优先复用 `shenwei-agent-product-w1-fix1` 的 Agent Loop、工具注册、参数校验、错误分类、预算、事件记录、会话续跑和测试体系。

当前只实现了产品、库存和物流三个只读工具，因此第一阶段还需要扩展：

- 客户、订单、应收和工单工具。
- CRM/SCRM 与知识库连接。
- 文档、表格和公开搜索能力。
- 通用插件/技能注册机制。
- 写动作确认与真实系统接入。

## 验收

- 至少 5 个跨部门 Demo 任务可以连续演示。
- 每个事实都能追溯到模拟系统或知识来源。
- 缺信息时主动追问，不自行编造。
- 工具调用、模型请求和最终结果均可回放。
- 报价计算不产生台账记录，所有事实和计算依据可追溯。
- 同一会话能够继续上下文，任务中断后有明确状态。
