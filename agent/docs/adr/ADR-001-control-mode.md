# ADR-001 · 主案例用动态 Loop 而不是固定流程

日期 2026-10-24 · 状态 accepted · 关联 1.3

## 场景

"查 X200 的规格和当前库存交期"。三种做法：直接模型调用（无实时数据，不能凭空知道库存）；固定流程（校验型号 → 查两个接口 → 汇总）；动态 Loop（每轮由模型选工具或回答，宿主控制执行与预算）。

## 候选与比较

同一输入、同一数据、同样的错误处理（见 `scripts/fixed_flow.py` 与 `evals/datasets/w01-control-mode.md`）：

| 输入 | 固定流程 | Loop |
|---|---|---|
| 查规格和交期 | 完全覆盖 | 覆盖 |
| 只问规格 | 多查一次库存，或加分支 | 模型自行只查规格 |
| "上次那个型号" | 需要会话状态分支 | 从历史里取 |
| 库存超时后解释 | 固定文案 | 模型按错误类别措辞 |

## 选择

主案例承认可以固定实现。本课程选动态 Loop，因为后续周的请求是可变的（比较型号、缺信息追问、失败后解释、多诉求），固定流程每加一类请求就加一条分支。

## 收益与代价

收益：请求形态变化不改控制流；工具扩展只改注册。代价：不确定性（选错工具、多调一次）、每轮一次模型请求的成本与时延、需要预算与证据设施。

## 什么变化会让我重新考虑

任务稳定且成本敏感、不允许波动（如定时对账）时回到固定流程；W7 再问一次"要不要多 Agent"，W11 问"要不要缓存"，同一种取舍。
