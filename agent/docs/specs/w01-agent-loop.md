# 周 spec · W1 从需求到 Agent Loop

本周承担（引用 `product.md`）：US-01 对话与轨迹（主线）；US-03 查订单（只作独立变体，W2 正式）；产品级 AC-01（事件日志能复原每一步请求、继续会话不丢轮次）。

## 1 本周任务一句话

"查一下 X200 的规格和当前库存交期。"

## 2 任务分解

| 步 | 需要什么 | 谁负责 | 产出 | 分支 |
|---|---|---|---|---|
| 解释请求 | 用户文本 | 模型 | 型号 + 想要的事实 | 型号缺失 → 追问 |
| 选择能力 | 工具说明 | 模型 | 工具请求（name、arguments、call_id） | 请求未知工具 → 拒绝并回注 |
| 查规格 | 型号 | 宿主执行 `get_product_spec` | 规格、来源版本 | 404 → 业务无数据，不是失败 |
| 查库存交期 | 型号、数量 | 宿主执行 `get_availability` | 可用量、最早发运日、观测时间 | 超时 → 失败类别 timeout，不是零 |
| 组织答复 | 工具结果 | 模型 | 答复文本 | 无有效结果 → 说明无法确认，不编 |
| 决定继续或停止 | 响应形态、预算 | 宿主 | 停止原因 | 步数耗尽 → stopped |

## 3 规格

- 目标：根据工具事实回答型号规格与库存交期。
- 非目标：报价写入、确认、后台持久执行、多 Agent、流式输出、知识检索。
- 输入：请求文本、已有完整历史、允许工具清单。
- 输出：答复或澄清；同时有运行状态与停止原因。
- 权威事实：ERP 工具的返回（fixture 是它的本地快照）。
- 允许：模型选择调不调工具、调哪个、调几次；只读工具重复读取在预算内不算错。
- 禁止：执行未注册工具；把工具错误包装成业务事实；把未配对的工具消息发给模型；密钥进事件。
- 缺信息：型号缺失或为空 → 不调 ERP，向用户追问。
- 上游失败：404 → 业务无数据；超时 / 5xx / 非 JSON → 失败类别，回注模型，由模型向用户说明。
- 结束：有效最终答复 → completed；步数或墙钟耗尽 → stopped；协议异常 → failed。
- 非功能：max_steps 默认 6；模型单次超时 60 s；工具单次超时 5 s；墙钟 120 s；密钥只在 `.env`，不进代码、事件、日志、提交。
- 证据：每次模型请求的快照（messages、tools、model、参数）与每次工具请求 / 执行 / 结果进事件文件；回放只读事件。

## 4 周级验收 W1-AC

| 编号 | 条件 | 验证方式 | 设计位置 | 证据 |
|---|---|---|---|---|
| W1-AC-01 | 只有已注册工具可执行 | 程序测试 T05 | ToolRegistry | 未知名称不进入函数，调用计数 0 |
| W1-AC-02 | model 缺失或为空时，业务函数调用次数为零 | 程序测试 T06 | 参数验证（guardrails） | FakeERP 调用数 0 |
| W1-AC-03 | 每个工具请求的结果保留对应 call_id | 程序测试 T03 / T04 | Loop 与消息适配 | 下一轮实际 messages |
| W1-AC-04 | 达到 max_steps 后不再发起新的模型请求 | 程序测试 T10 | Loop 预算 | 调用次数与 stop_reason |
| W1-AC-05 | 工具超时记录为失败，不能包装成"库存为零" | 程序测试 T08 | ERP adapter 与错误模型 | 错误类别与回注内容 |
| W1-AC-06 | 最终答复中的规格与交期由有效工具结果支持 | 真实模型案例 + 人工判定（evals/） | 指令、上下文与模型 | 冒烟记录 |
| W1-AC-07 | 回放历史记录不调用模型与工具 | 程序测试 T13 | Replay | 外部调用计数 0 |

W1-AC-01–05、07 可程序测；W1-AC-06 是模型质量，另建真实模型案例及判定标准。
